# langchain-miniopenclaw 系统优化计划

系统架构理解简图（三大层 + 两条流的鸟瞰视角）：

```
┌─────────────────────────────────────────────────┐
│                  FRONTEND (Next.js 14)            │
│  ChatInput → ChatPanel → ChatMessage             │
│               └→ AnswerTraceTimeline (进度条)      │
│               └→ ThoughtChain (规划回溯)           │
│               └→ RouteCard / EvidenceCard / ...   │
│  API Gateway: api.ts (SSE/JSON) ←→ FastAPI        │
├─────────────────────────────────────────────────┤
│                BACKEND (FastAPI 8002)              │
│  Engine: answer() / stream_answer()               │
│    ├→ quick_flow (单轮: 路由→检索→生成)            │
│    └→ deep_flow  (多轮: 规划→执行→评估, max4轮)    │
│  Router: query_router → tcm_intent_classifier     │
│  Planner: planner_actions → planner_runtime       │
│  Evidence: evidence_coverage → evidence_selector  │
│  LLM Client: GroundedAnswerLLMClient → OpenAI API │
├─────────────────────────────────────────────────┤
│              SIDECARS (HTTP / local)               │
│  Graph (8101): runtime_store / nebula / fallback  │
│  Retrieval (8102): files_first / case_qa / chroma │
│  Pipeline scripts: triple extraction KG           │
└─────────────────────────────────────────────────┘
```

## P0 — 高价值 / 低风险 / 可立即执行

### 0.1 消除 quick_flow / deep_flow 的 54% 代码重复

| 方面 | 详情 |
|---|---|
| **文件** | `backend/services/qa_service/quick_flow.py` (226 行), `deep_flow.py` (314 行) |

| **风险** | 低 — 纯提取，不改变行为 |

### 0.3 给 QAService 单例加锁

```python
# engine.py:373-380 — 当前实现
_qa_service: QAService | None = None
def get_qa_service() -> QAService:
    global _qa_service
    if _qa_service is None:      # ← 竞态条件
        _qa_service = QAService()
    return _qa_service

# → 改为:
import threading
_lock = threading.Lock()

def get_qa_service() -> QAService:
    global _qa_service
    if _qa_service is None:
        with _lock:
            if _qa_service is None:
                _qa_service = QAService()
    return _qa_service
```

## 架构亮点总结

此次审查同时发现以下架构决策值得肯定：

| 亮点 | 说明 |
|---|---|
| **Evidence Path URI 方案** | `entity://` / `book://` / `chapter://` / `alias://` / `caseqa://` 提供可读、可审计、可调试的证据层 |
| **优雅降级链** | Deep→Quick→LLM retry→Deterministic fallback，每层都有明确 gate；AGENTS.md 明确禁止 mock 数据静默降级 |
| **Multi-round 深度模式的状态机设计** | `_init_coverage_state` → `_update_coverage_state` → `_identify_evidence_gaps` 形式化程度高 |
| **前端 SSE 事件模型** | `chatEvents.ts` 中 11 种事件类型定义清晰，类型安全，证据去重逻辑在客户端实现 |
| **Tailwind 语义色板** | `tailwind.config.ts` 中使用 `ocean/ember/sand/frost/ink` 语义别名，而非硬编码十六进制值 |
| **Files-first 优先** | 与 AGENTS.md 方向一致，结构化 QA 索引已经是默认主路径 |
| **前端流控 + AbortController** | SSE stream 可中断，资源清理正确 |
